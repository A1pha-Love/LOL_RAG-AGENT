# 代码注释规范

> 本文件说明本项目的注释写法，供后续贡献者与学习者参考。
> 主体内容与 `.cache/annotation_style_guide.md`（执行时的内部规范）一致，
> 此处保留为仓库内的长期约定。

本项目核心代码（`src/`、`apps/`、`frontend/src/`，共 25 个文件）已按本规范补充详细
中文注释，用于说明 RAG 检索链路、Agent 编排、流式输出与前端响应式的实现取舍。

**一个重要例外**：`src/lol_agent/agent.py` 与 `tools.py` 中 `@tool` 装饰的函数
docstring **保持英文且逐字不变**——它们会作为工具描述进入模型提示词，改动即改变行为。
这些工具的中文说明写在 docstring 下方的 `#` 注释块中。

本文件是给负责补注释的执行者看的统一规范。**所有文件必须遵守**，以保证风格一致。

## 一、目标读者

**正在学习 RAG / Agent 工程实践的人**。他们能读代码，但不了解本项目的设计取舍、踩过的
坑、以及"为什么这么写而不是那么写"。注释的价值在于把这些**讲出来**。

## 二、最重要的红线

1. **绝不改变代码行为**。只增删注释与文档字符串，不改任何可执行语句、类型标注、import、
   常量值、函数签名。
2. **不删除原有的"为什么"注释**。现有英文注释包含大量实测结论与踩坑记录（例如"此处的
   刷新刻意不 await，因为 await 曾导致整个界面卡死"）。这些是项目最宝贵的部分，必须
   保留其含义，可在其旁补中文说明。
3. **不臆造**。不确定某段逻辑为何这样写，就只描述它**做了什么**，不要编造理由。若发现
   可疑之处，用 `# 注意：` 如实提出疑问，而不是断言。

## 三、注释风格

### Python

模块开头：保留原有英文 docstring（它是权威说明），在其**下方**另起一段中文说明：

```python
"""Original English docstring, unchanged.
"""

# ============================================================================
# 中文说明
#
# 这个模块解决什么问题、在整体架构中的位置、与哪些模块协作。
# 若有重要的设计取舍或历史原因，在这里说清楚。
# ============================================================================
```

函数/方法：docstring 用中文，包含用途、参数含义、返回值、以及**非显然的约束**；复杂函数
在语句旁加行内注释。

```python
def f(x: int, *, flag: bool = False) -> str:
    """一句话说明这个函数做什么。

    参数:
        x: 它的含义与取值范围。
        flag: 它改变什么行为；默认值为什么是这个。

    返回:
        返回什么；什么情况下会抛出异常。
    """
    # 为什么需要这一步（而不是仅描述它做了什么）
    y = x * 2
    return str(y)
```

行内注释的要求：

- **解释"为什么"**，而不是复述代码。`i += 1  # 自增` 这种没有价值。
- 对**非显然**的地方加注释：边界条件、平台怪癖、性能取舍、绕过某个 bug 的原因、
  与外部系统约定的格式。
- **不要每行都加**。逐行堆砌会让代码难以阅读。目标是"每一处需要解释的地方都有解释"，
  而不是"每一行都有注释"。对确实一目了然的赋值、return、简单调用不必加。

### TypeScript / Vue

- 文件顶部加块注释，说明该文件职责与在界面中的位置。
- 导出的函数、组合式函数、props、emits、响应式状态加中文说明。
- 复杂逻辑处加行内注释；`.vue` 的 `<script setup>` 与 `<template>` 内均可用
  `<!-- -->` / `//` 说明结构意图。

```ts
/**
 * 中文说明：这个模块做什么、被谁使用。
 */

/** 会话摘要；pinned 为 1 表示已置顶。 */
export interface SessionSummary { /* ... */ }
```

## 四、特别值得解释的内容

这些是本项目最有学习价值的地方，遇到时**务必**详细说明：

- **RAG 检索链路**：分块策略（按标题路径）、两阶段检索（向量召回 → rerank）、
  阈值的作用与来源、干扰文档为何被排除。
- **Agent 机制**：LangGraph 图的节点与边、工具何时被调用、多轮对话如何改写检索查询、
  `ContextVar` 为什么能保证并发安全。
- **流式输出**：SSE 的字节格式（本项目用 CRLF）、分帧解析为何要按规范处理 CR/LF/CRLF、
  超时兜底的三档阈值各防什么。
- **前端响应式**：为什么推入 `reactive` 数组的对象必须是 `reactive(...)`（否则写入绕过
  代理，界面不更新）、为什么某些刷新**不能 await**。
- **确定性**：为什么统计由 Python 算而不让模型估算；为什么会话顺序按真实活动而非点击。
- **错误与降级**：额度耗尽、索引缺失、rerank 不可用时的行为。

## 五、完成后必须自检

1. **语法与行为未变**：Python 用 `python -X pycache_prefix=<临时目录> -m py_compile <文件>`；
   前端用 `npm run typecheck`。
2. **测试仍全部通过**（见仓库根 README 的检查命令）。
3. 报告：改了哪些文件、各增多少行注释、自检结果。**若某项无法验证，必须明说**。
