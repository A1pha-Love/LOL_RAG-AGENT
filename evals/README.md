# Agent 评测集

`cases.jsonl` 保存固定的中文问题、预期的 Agent 工具操作和数据参考答案。工具名对应 `src/lol_agent/tools.py` 的 Agent-facing 函数；底层公式位于 `src/lol_agent/metrics.py`。参考答案按 `gameId` 去重后的 51,053 场比赛计算；数据时间范围为 2017-06-08 至 2017-09-06 UTC。英雄统计以数据中的 ID 为准，并可用 Riot Data Dragon 7.17.1（zh_CN）静态快照中的中文 name/title 或英文标识符查询；138 个 ID 的名称字段已全量核对，该映射不提供逐场补丁信息。

## 统计工具基线：cases.jsonl

- 对局去重计数
- 英雄出场数、胜场、胜率及 Top 3
- 禁用对局数、Ban 率及 Top 3
- 首个事件发生率与取得事件队伍的条件胜率
- 平均对局时长
- **召唤师技能出场率、被选时胜率、携带/未携带胜率对比**（含分母口径断言）

**这 15 条用例现在由 `tests/test_eval_cases.py` 在每次离线检查中执行**，不调用模型、不消耗额度。
此前它们只是文档中的参考值，没有任何代码执行过。`evals/README.md` 要求「参考值应在评测实现前
独立复核」，该测试即满足这一要求：逐字段核对 `expected`、校验 Top N 的 ID 顺序，
并验证每个百分比确实等于自身分子/分母——只比分子分母的话，一个算错比例的指标仍会通过。
**新增工具时必须同时补一条参考案例**，否则该工具不在回归覆盖内（测试会检查覆盖度）。

## 判分口径

- `expected` 中保存分子、分母和单位；百分比的值按 `numerator / denominator * 100` 计算，时长按 `numerator / denominator` 计算。
- 数值比较建议容差不超过 `1e-6`；Agent 面向用户的展示可四舍五入，但分子、分母和指标口径必须一致。
- 对 Top N 结果，ID 和排序必须一致；并列时需按指标字典补充稳定的次序规则。
- 除数为 0 时应返回“无样本”，不能伪报为 0%。
- 这组用例评估本地统计工具的选择和数值口径，不单独评估模型回答文风。

## RAG 与 Agent 用例：rag_cases.jsonl

该文件覆盖统计工具与知识检索工具的组合、文档来源召回、口径说明、数据边界、因果表述和指令注入场景。字段说明：

- `expected_tools`：回答该问题应调用的工具集合；调用顺序不要求固定。
- `forbidden_tools`：在拒答或数据不支持的问题中不应调用的无关统计工具。
- `expected_retrieval`：前 K 条检索结果中至少应出现的来源路径和 Markdown 标题。
- `answer_must_include`：答案应表达的事实或限制；按语义判定，不要求逐字匹配。
- `answer_must_not_claim`：答案不得作出的无依据断言。
- `numeric_assertions`：需要与确定性统计工具结果对齐的分子、分母和单位。

RAG 用例按三部分分别评分：工具选择、来源召回、答案事实约束。引用来源路径与标题正确但答案事实错误，仍判失败；来源未召回但答案碰巧答对，也不能判为检索通过。涉及颜色方胜率、当前版本、分路和因果的用例重点检查不得编造或越出数据边界。

`evaluate_rag.py` 会对 `answer_must_include` 做标点/空白规范化后的字面匹配；单项可写成短语数组以提供等义表达。对禁止断言会检查字面命中附近是否有常见否定词，并将未被否定的命中标记为潜在违规。该自动检查是筛查提示，无法可靠理解所有语义、否定范围或反讽，仍需人工复核。

运行 RAG/Agent 用例：

    .\.venv\Scripts\python.exe scripts\evaluate_rag.py

只重跑指定用例时可重复传入 `--case-id`，例如 `--case-id unsupported_current_meta --case-id prompt_injection_guardrail`。

该脚本逐条调用配置的 Qwen Chat API；需要 Embedding API 检索时也会产生相应调用费用。脚本自动核对工具选择、来源标题和结构化数值，答案中的事实约束及禁止断言仍需人工复核。

**`expected_retrieval` 已经可以零配额验证**：`scripts/verify_retrieval_offline.py` 读取同一份
`rag_cases.jsonl`，用缓存向量按 embedding 顺序断言来源召回，并已接入离线检查。
因此重跑 `evaluate_rag.py` 只为验证「工具选择 + 答案措辞 + 禁答断言」三件事，
来源召回不必再靠它。

**新增检索用例的正确流程**：先用 `scripts/validate_retrieval_candidates.py` 确认目标
(source, heading) 真的能进 top K，再写入用例。否则会留下一条必然失败的断言——
标题必须与文档中的 Markdown 标题逐字一致，写成大概意思会永远匹配不上。

检索无匹配阈值校准使用 `retrieval_calibration.jsonl` 中的相关与无关查询，运行：

    .\.venv\Scripts\python.exe scripts\calibrate_retrieval.py

该脚本将校准集中的短查询合并为一次 Embedding API 批量请求，对比相关与无关问题的最高相似度，并检查相关来源是否进入前三条；只有分数有清晰间隔时才建议临时阈值。校准查询不包含原始 CSV 或文档正文。样本仍有限，不能替代后续扩展评测集。

初始 7 条查询校准中，相关问题最高分为 `0.4839–0.6392`，无关问题为 `0.1943–0.2567`，因此检索暂用最低分 `0.3703` 过滤无匹配结果。扩充至 16 条查询后，相关最高分范围为 `0.4839–0.6750`，无关最高分范围为 `0.1942–0.2579`，建议中点为 `0.3709`。因新旧中点仅相差 `0.0006`，且两类分数仍有明显间隔，暂时保留 `0.3703`。该阈值仍是临时值，需继续用更多真实问法验证。
