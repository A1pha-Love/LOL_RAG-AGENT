# 数据审计结果与字段取值分布

本文件记录对原始 CSV 的只读审计结果。审计过程以只读方式打开源文件，
不写回、不转换、不清理。

## 文件结构

原始 CSV 的规模与结构：**共 51,490 数据行、61 个字段（列）**。
按 `gameId` 去重后为 **51,053 场**对局，即 437 条重复行；去重规则见
「去重规则与重复数据处理」。

- 数据行数（原始行数）：**51,490**
- 字段数（列数）：**61**
- 字段数不一致的行：0
- 缺失值：**没有任何字段存在空值**
- 无法解析的数值：**0 处**（`gameDuration`、`creationTime` 及各队伍目标字段均可解析）

**注意区分**：原始行数 51,490 是文件里的行数，去重后的对局数是 51,053，
回答"有多少场比赛"时应使用去重后的数。

| 字段 | `0` 未发生 | `1` team1 | `2` team2 |

| 项目映射的英文标识符正确 | 138 个逐项比对 | ✅ 零不一致 |

### 两处需要限定的表述（本次核实修正）

1. **`-1` 哨兵的出处**：该条目（`id=-1`、`name=None`）**只出现在
   `champion_info_2.json`（7.18.1）**，`champion_info.json`（7.17.2）里没有。
   原先笼统写作"数据集自带的 `champion_info.json`"，已限定版本。
2. **项目快照与附件版本不同**：项目锁定 Data Dragon **7.17.1**（zh_CN），
   附件是 **7.17.2**（en_US）。已实测两者**英雄集合与英文标识符→数值 ID 的映射
   完全一致（138/138，零差异）**，因此不影响名称映射；但版本号确实不同，
   引用时应说明所据版本。

### 仍存在的边界（不是缺陷，是数据本身的性质）

- 两个文件**语言不同**（项目 zh_CN / 附件 en_US），因此中文标签**无法**与附件逐字比对；
  可严格比对的是英雄集合与 ID 映射，这部分已全量核对。
- CSV 无逐场 `patch` 字段，任何按补丁切片的分析都不成立——这一点未变。
