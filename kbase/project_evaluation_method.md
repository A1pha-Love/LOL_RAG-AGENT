# 评测方法与判分口径

## 两类评测集

- **统计参考案例**：固定中文问题 + 预期的工具调用 + 数据参考答案（分子、分母、单位）。
  标准答案按 `gameId` 去重后的 51,053 场比赛计算。
- **RAG / Agent 用例**：覆盖统计工具与知识检索工具的组合、文档来源召回、
  口径说明、数据边界、因果表述和指令注入场景。

## RAG 用例的字段含义

- `expected_tools`：回答该问题应调用的工具集合，**调用顺序不要求固定**。
- `forbidden_tools`：在拒答或数据不支持的问题中**不应调用**的无关统计工具。
- `expected_retrieval`：前 K 条检索结果中至少应出现的来源路径与 Markdown 标题。
- `answer_must_include`：答案应表达的事实或限制；按语义判定，不要求逐字匹配。
- `answer_must_not_claim`：答案不得作出的无依据断言。
- `numeric_assertions`：需要与确定性统计工具结果对齐的分子、分母和单位。

## 判分原则

RAG 用例按三部分分别评分：**工具选择、来源召回、答案事实约束**。

- 引用来源路径与标题正确但答案事实错误，仍判失败。
- 来源未召回但答案碰巧答对，也不能判为检索通过。
- 涉及颜色方胜率、当前版本、分路和因果的用例，重点检查不得编造或越出数据边界。

## 来源召回的匹配口径

知识库按标题分块，检索结果中的 `heading_path` 是**完整标题路径**
（形如 `文档标题 > 节 > 小节`），而不是单一标题。

因此 `expected_retrieval` 里的 `heading` 按**子串**匹配：
只要该标题出现在命中分块的标题路径中即算召回。
`source` 仍要求与命中分块的文件路径完全一致。

## 退出码

评测脚本的退出码默认检查四项：

1. 工具选择（`expected_tools` 全部调用、`forbidden_tools` 均未调用）
2. 来源召回（`expected_retrieval` 全部命中）
3. 结构化数值断言（`numeric_assertions` 全部一致）
4. 未被否定的禁答断言数量为 0

**答案短语包含项（`answer_must_include`）默认只报告、不影响退出码**，
因为它是字面匹配、无法判断语义与否定范围。
需要把这一项也纳入门禁时，使用 `--strict`。

## 自动检查的局限

自动脚本对 `answer_must_include` 做标点与空白规范化后的**字面匹配**，
单项可写成短语数组以提供等义表达。对禁止断言会检查字面命中附近是否有常见否定词，
并将未被否定的命中标记为潜在违规。

**该自动检查只是筛查提示，无法可靠理解所有语义、否定范围或反讽，仍需人工复核。**
自动答案包含项的通过数量**不应单独作为质量结论**。

## 检索阈值校准

使用相关与无关查询的对比集，比较两类查询的最高相似度，并检查相关来源是否进入前三条。
只有在两类分数有清晰间隔时才建议临时阈值。

历史上：初始 7 条查询校准得到相关问题最高分 0.4839–0.6392、无关问题 0.1943–0.2567，
据此暂用最低分 `0.3703` 过滤无匹配结果。扩充到 16 条后建议中点变为 0.3709，
与旧值仅差 0.0006，因此暂未调整。**该阈值仍是临时值，需要更多真实问法验证。**

## 当前评测的已知缺口

- 完整案例套件**只在提示词最后一次加强之前运行过一次**，
  之后仅定向复测了受影响的两条用例，因此当前提示词版本没有完整回归结果。
- 自动评测脚本的**退出码不检查答案事实包含项**，
  因此答案漏答不会导致评测失败，这一点需要修正。
