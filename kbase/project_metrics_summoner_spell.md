# 召唤师技能指标口径

## 数据来源与字段结构

CSV 中每场比赛有两支队伍，每队 5 名选手，**每名选手固定 2 个召唤师技能槽位**：

```
t1_champ1_sum1   t1_champ1_sum2      # 队伍 1 第 1 名选手的两个技能
t1_champ2_sum1   t1_champ2_sum2      # …第 2 名选手
...
t2_champ5_sum1   t2_champ5_sum2
```

共 `2 队 × 5 选手 × 2 槽位 = 20 列`。字段值是召唤师技能的数字 ID
（例如 `4` = 闪现），名称由 Riot Data Dragon 快照映射（见 `docs/mapping_summoner_spells.json`）。

**两个槽位是无序的。** 数据没有说明 `_sum1` 是"主技能"还是"先排序的那个"，
因此**不得**把槽位顺序解读为优先级、选取顺序或重要程度；任何按槽位切分的统计
都需要独立命名并说明依据。

## 技能出场率（队伍口径）

公式：**出场该技能的队伍数 ÷ 全部队伍出场次数 × 100%**。

- **分母是队伍出场次数 = 去重后比赛数 × 2**，不是比赛数。因为技能由一支队伍携带，
  同一场比赛里两支队伍可能都带同一技能。
- **同一队伍内同一技能只计 1 次**：即使该技能同时出现在 `_sum1` 与 `_sum2`
  （两名选手都带），该队伍也只贡献 1。因此这是"**队伍是否携带了该技能**"，
  而不是"技能槽位占比"。

> 若需要"技能槽位占比"（即 20 个槽位中有多少比例是某技能），那是**另一个指标**，
> 必须使用独立名称，不能沿用"出场率"。

## 技能被选时胜率

公式：**携带该技能且获胜的队伍数 ÷ 携带该技能的队伍数 × 100%**。

分母只包含携带该技能的队伍，因此**不等于**全局胜率（全局恒为 50%）。

## 携带 / 未携带对比

`get_spell_win_split` 同时给出两侧：

- **携带**：该队伍携带了此技能；
- **未携带**：该队伍没有携带此技能。

两侧都基于同一批比赛，**队伍数之和恒等于 去重后比赛数 × 2**。

## ⚠️ 解读限制（必须随数字一起给出）

**这是观测数据，不是受控实验。** 技能胜率差异同时受以下因素影响：

1. **英雄与定位选择**：需要位移的英雄更倾向带闪现；打野几乎必带惩戒。
2. **对局内因**：技能选择本身是对敌方阵容的应对，存在反向因果。
3. **近似普适的技能缺乏区分度**：闪现的出场率约 **99.998%**
   （102,104 / 102,106 队伍出场），几乎人人携带。它的胜率必然接近 50%，
   **不能**据此得出"闪现无用"或"闪现不提升胜率"的结论——没有对照组可言。
4. **样本量差异**：净化等低频技能的队伍数只有约 3,000，其胜率的抽样波动
   远大于闪现、惩戒等高频技能。

因此这类结果只能作为**描述性统计**呈现，必须标注不确定性，
**不得推导为因果或给出"应该带什么技能"的建议**。

## 已知数据边界

- CSV **不含**玩家段位、位置、对局时长分布之外的上下文，因此无法做位置分层的技能分析。
- CSV **不含**逐场补丁号，技能强度随版本变化的影响无法从本数据分离。
- 映射文件同时包含已停用技能（ID 35、36），**本数据集从未出现**；
  查询这些 ID 应返回"未识别"，而不是伪造一行 0 数据。
